# 공문서 작성 규약 (kordoc 공문서 모드용 마크다운) — GIL 재구성

근거: 행정안전부 「행정업무운영편람」·「행정업무의 운영 및 혁신에 관한 규정 시행규칙」. 렌더(부호·정렬·여백·글꼴)는 `kordoc generate --preset`이 맡고, 이 문서는 **Claude가 초안 마크다운을 어떻게 써야 엔진이 바르게 읽는가**를 정한다. (kordoc `gongmunseo` 스킬·`docs/gaejosik-munche.md`(MIT) 재구성)

## 1. 위계 — 헤딩·리스트 깊이가 곧 항목부호

| 마크다운 | 기안문·통지·회의록·계획서(법정형) | 보고서·개조식·업무보고 |
|---|---|---|
| `#` | 제목(가운데·크게) / 기안문은 행정기관명 | 제목(표지 제목) |
| `##` | `1.` `2.`(장) | `Ⅰ.` `Ⅱ.` 장 띠(장마다 새 쪽) |
| `###` | `가.` | `□` 대항목(한 줄 자동 축소, 넘치면 경고) |
| 리스트 깊이 0 (0칸) | `1.` | `ㅇ`(`--bullet2 ○`이면 `○`) |
| 깊이 1 (2칸) | `가.` … `하.` | `-` |
| 깊이 2 (4칸) | `1)` | `ㆍ` |
| 깊이 3 (6칸) | `가)` | |
| 깊이 4~7 | `(1)` `(가)` `①` `㉮` | |

- 들여쓰기 **2칸 = 1단계**. 마커 종류(`-`/`1.`)는 무시되고 깊이만 본다. 본문에 `□/ㅇ/-/1./가.`를 직접 써도 같은 깊이로 정규화된다.
- **항목이 하나뿐이면** 리스트로 만들지 말고 문단으로 쓴다(단일 항목 부호 생략 규정; `--suppress-single`).
- 업무보고 프리셋: `###`=파란 숫자칸 절, `####`=남색 소제목 박스 "1.", `#####`=① 하늘색 항목 띠, `> ▪ …` 인용문=연노랑 성과 요약박스, `## 별첨 …`=별첨 띠, □·❶ 뒤 `(키워드)`·`[키워드]`는 자동 파랑 굵게.

## 2. 문서별 골격

### 기안문·시행문
```
# ○○구청                                  ← 행정기관명(가운데). --doc-head 를 쓰면 두문표가 대신 붙음
수신  ○○○장관(○○과장)                      ← 없으면 "수신  내부결재"
(경유)
제목  ○○○○ 알림

1. 관련: ○○과-0000(2026. 6. 1.)
2. ○○에 대하여 다음과 같이 알려드리니 협조하여 주시기 바랍니다.
  - 일시: 2026. 7. 1.(수) 14:00∼16:00
  - 장소: ○○구청 ○○실

붙임  ○○ 계획서 1부.  끝.

<center>○ ○ 구 청 장</center>                 ← 발신명의(가운데). --doc-foot 를 쓰면 결문표가 대신 붙음
```
- `--doc-head "org=기관명,slogan=원훈,to=수신,title=제목"` · `--doc-foot "sender=발신명의,drafter=주무관 홍길동,reviewer=과장 김철수,approver=국장 박영희,cooperator=협조자,docNum=과-번호 (날짜),receive=접수,zip=우편번호,address=주소,site=홈페이지,phone=전화,fax=전송,email=메일,disclosure=공개"` → 별지 제1호서식 두문표·결문표(서울 실결재 6행 표).
- 어투: 경어 종결(`~하시기 바랍니다`). 통지·공고는 `--notice-head "no=공고 제2026-1호,date=…,sender=…"`.

### 보고서(1건 1매 요약보고)
```
# ○○ 개선방안 보고
> 3분기 지표 변동과 대응 계획을 검토하고자 함        ← 제목 직후 인용문 = 요약박스. 한 문장·부호 없음·3줄(90~100자) 이내 필수

## 추진 배경
□ 환율 변동성 확대에 따른 원가 점검 필요
 ㅇ 3분기 변동폭 4.2%
  - 원자재 수입 비중 63%
## 주요 지표
| 구분 | 2분기 | 3분기 |
|---|---|---|
## 향후 계획
※ 출처: 재무팀 월간 보고                          ← ※/출처:/자료: 줄은 참고(작은 글씨)
```
- 종결은 명사형(`~함/~임/~음/~필요`), 서술형 `~다` 0%. `--report-info "(날짜, 부서 담당자, ☎)"` 담당자 행, `--summary`로 요약박스 대체 지정 가능.
- 리드문 형식 `[수단]하고, [수단]하여 [목적]하고자 함.`(140자 이내, 한 문장).

### 개조식(정부 표준 보고서, 표지·목차)
`--preset 개조식 --org 기관명 --dept 부서 --date "2026. 9. 28." --doc-info "docNum=…,disclosure=공개"` — 표지·목차·Ⅰ.Ⅱ. 장 헤더·쪽번호 기본 on(`--no-cover --no-toc --no-page-numbers`로 끔). 본문 첫 쪽 제목 반복 박스 `--no-body-title-box`.

### 계획서 / 회의록
계획서는 5W2H(목적·근거·기간·대상·내용·방법·예산) 골격, 회의록은 법정 9요소(회의명·일시·장소·참석자·안건·발언 요지·결정 사항·조치 사항·작성자).

### 보도자료
`--preset 보도자료 --press-head "release=보도시점,distribute=배포일,dept=담당부서,manager=담당자,phone=연락처" --press-sub "부제1;부제2"`.

## 3. 표기법(엔진이 고쳐주지 않음 — `lint`가 잡음)

| 항목 | 규칙 | 예 | lint 코드 |
|---|---|---|---|
| 날짜 | `YYYY. M. D.` 온점+1칸, 0 제거, 끝에도 온점 | `2026. 6. 19.(금)` | `DATE_ZERO_PAD`·`DATE_KOREAN` |
| 기간 | 물결 `∼`(앞뒤 붙임) | `6. 1.∼6. 15.` | `TILDE_SPACE` |
| 시각 | 24시각 `HH:MM` | `09:00∼12:00` | `TIME_COLON_SP`·`TIME_AMPM` |
| 금액 | 숫자+한글 병기, 붙여 씀 | `금113,560원(금일십일만삼천오백육십원)` | `MONEY_*` |
| 붙임 | `붙임` 뒤 2칸(쌍점 없음), 1개면 번호 생략 | `붙임  ○○ 1부.  끝.` | |
| 끝 | 본문·붙임 끝에 2칸 띄우고 `끝.` | `…바랍니다.  끝.` | |
| 법령명 | 낫표 | `「행정업무의 운영 및 혁신에 관한 규정」` | |
| 쌍점 | 앞 붙이고 뒤 1칸(표 셀 라벨 `성 명 :`은 예외) | `일시: 2026. 6. 19.` | |
| 곧은따옴표 | 자동으로 ‘’“” 변환 | | |
| 외래어·두음·차별어 | 행정용어로 | 파일럿→시범, 리스크→위험 요인, 벤치마크→준용 | `LOANWORD_ERROR`·`DUEUM_ERROR`·`DISCRIMINATORY_TERM` |

## 4. 개조식 문체 검수(`lint --munche`, 보고서·계획서·개조식만)

| 코드 | 등급 | 잡는 것 | 고치는 방향 |
|---|---|---|---|
| `DA_ENDING` | error | `~다` 서술형 종결 | 명사구 또는 `~함/있음` |
| `DEONTIC` | error | `~해야 한다` 당위 | `⇒ ○○ 필요` |
| `RHETORIC_CONTRAST` | error | `A가 아니라 B`의 B가 추상어 | 지우거나 구체 선택지로 |
| `QUESTION_EXCLAIM` | error | 본문 물음표·느낌표 | 지움 |
| `GEOSIDA`·`COUPLET` | warning | `~것이다`, 대구 슬로건 | 명사·수치 종결 |
| `ITEM_LONG`(70자)·`CONCL_LONG`(60자) | warning | 항목·결론이 김 | 근거·예시는 세부(`-`)로 내림 |
| `LEAD_ENDING`·`LEAD_LONG` | warning | 리드문 형식·길이 | `…하고자 함.` 한 문장 |

실측(지자체 15건 2,288줄): □ 소제목 2~4어절, ㅇ 항목 중앙 31자, - 세부 48자 — **항목은 제목처럼, 세부는 설명처럼**.

## 5. AI 문체 흔적 제거(`AI_*` 룰)
- 줄표(— – ―) → 쉼표·괄호·가운뎃점(·). 볼드는 리드어·핵심 수치 한 곳만(한 줄 3회↑ `AI_BOLD_OVERUSE`).
- 선언·구호형 문장, 작은따옴표 강조 → 담백한 개조식.
- GIL 체인과의 관계: ◆최종본은 마크다운 초안에 `gil:ai-slop-reviewer → gil:korean-spell-check → gil:humanize-korean`을 먼저 돌린 뒤 `lint`로 마감한다(공문서는 humanize 강도 낮게 — 개조식 명사형을 서술형으로 풀지 않도록 지시).

## 6. 위계 타이포(`--levels`)·글꼴 처방(실결재 실측)

| 문서 꼴 | 관행 | 처방 |
|---|---|---|
| 법정 8단계 기안문 | 전 단계 본문과 동일 글꼴·크기 | 지정하지 않음(기본) |
| 전자결재 기안문·계획서 □/ㅇ/- | □ HY견고딕 +2~3pt 굵게, ㅇ 한컴돋움 굵게, - 휴먼명조 | `--preset 계획서 --bullet2 ㅇ --levels "0=HY견고딕/17/bold,1=한컴돋움/15/bold,2=휴먼명조/14"` |
| 보고서·개조식 □/○/- | □만 HY헤드라인M +1pt | 프리셋 기본값 — 지정 불필요 |

문법: `depth=글꼴/pt/bold` 쉼표 구분(depth 0~7). 미설치 글꼴은 경고만 내고 생성. 여백(위20·아래10·좌우20mm)·명조 15pt·줄간격은 편람 관행값 — 기관 요구 시 `--font/--pt/--line-spacing`.

## 7. 표·차트·수식·이미지
- 표: GFM 파이프표 → 실측 정부 서식(머리행 음영+이중선·외곽 굵은선·내용 비례 열폭). 참조 문서 서식 재현은 `profile` → `--profile`.
- 차트: ` ```chart ` 펜스. `type: column|bar|line|area|pie|doughnut|scatter|radar(+_stacked)`, `cat:` x축, `size: 120x70`(mm), `colors:`, 이후 `계열명: 값,값,…`. 펜스 안 주석 금지(값으로 들어감). 제목은 본문 문단으로.
- 수식: `$$…$$` → 네이티브 `<hp:equation>`(`\frac`·`\sqrt`·첨자·그리스·적분·행렬 부분셋).
- 이미지: `![](그림.png)` + `--image-dir 폴더`.
- 우측 정렬: `<right>텍스트</right>`, 가운데: `<center>…</center>`.
