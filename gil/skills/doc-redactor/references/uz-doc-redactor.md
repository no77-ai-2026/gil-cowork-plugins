# UZ 듀얼 — 우즈베키스탄 문서 개인정보 마스킹 (GIL 오리지널)

## 법적 배경(사실만)
- 우즈베키스탄 「개인정보에 관한 법률」(ЗРУ-547, 2019. 7. 2., 2021 개정)은 개인정보의 국내 서버 처리(현지화) 의무와 처리 동의를 규정한다. 문서를 국외(한국 본사·클라우드 AI)로 보내기 전 마스킹은 이 의무의 위험을 줄이는 실무 조치이지 적법성 판단을 대체하지 않는다 — 판단은 `gil:compliance-check`·`gil:legal-risk`(원문 확보 상한·2차 출처 표기 규칙 동일).

## kordoc 룰이 잡지 못하는 UZ 식별자 (수동 확인 목록)
| 식별자 | 형태 | 처리 |
|---|---|---|
| PINFL(ЖШШИР) 개인식별번호 | 숫자 14자리(`3 + YYMMDD + …`) | 룰 없음 → `--dry-run` 후 정규식 `\b\d{14}\b`로 별도 검색, `gil:hwpx-writer` patch 또는 마크다운 치환 |
| 여권 | 라틴 2자 + 숫자 7자리(`AA1234567`, 신형 `AD…`) | `passport` 룰이 한국 여권(M12345678) 패턴 위주 → 매칭 여부를 리포트에서 확인 |
| 신분증(ID card) | 라틴 2자 + 7자리 | 여권과 동일 처리 |
| 전화 | `+998 90 123 45 67`, `90-123-45-67`, `(71) 200-00-00` | `phone` 룰은 한국 형식 중심 → 공백·괄호 변형은 미탐지 가능, 정규식 `\+?998[\s-]?\d{2}[\s-]?\d{3}[\s-]?\d{2}[\s-]?\d{2}` 보조 |
| 은행 카드 | Uzcard/Humo 16자리 | `card` 룰(16자리) 매칭 — 확인 |
| 법인 INN(세무번호) | 숫자 9자리 | 개인 사업자(ЯТТ)의 INN은 개인정보로 취급 — 수동 |
| 주소 | `Toshkent sh., … tumani, … ko'chasi, 12-uy` | `address` 룰은 한국 주소 패턴 → UZ 주소는 수동 |

## 절차 보완
1. kordoc `redact --dry-run --json`으로 공통 룰 히트 확인.
2. 마스킹 마크다운(또는 HWPX 파싱본)에서 위 표의 정규식으로 2차 검색 — 히트는 `[UZ-PINFL]` 같은 태그로 치환.
3. 러시아어·우즈베크어 인명(성-이름-부칭 3어절, 키릴/라틴)은 `name` 룰이 잡지 못한다 — 문서가 인사·법무용이면 사용자와 인명 목록을 정해 일괄 치환.
4. 결과 보고에 "UZ 식별자 수동 확인 완료/미완료"를 한 줄로 남긴다.
