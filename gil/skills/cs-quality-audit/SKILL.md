# 고객지원 산출물 검수

원본을 수정하지 않고 고객 메시지·리뷰 원자료·셀러 정책과 산출물을 대조한다.

- 분류 우선순위, 이관 수준, VOC 범주마다 근거가 되는 원문이나 데이터 위치를 기록한다. 인용 내용이 판정을 뒷받침하는지 확인한다.
- 환불·보상·배송일·정책 예외 약속에 셀러 승인이 있는지 확인한다. 승인 근거가 없다면 결정 항목으로 표시됐는지 본다.
- 한국어 경어, 책임 전가 표현, 불만을 키우는 어조를 검수한다. 법적 민감 사안에 담당자 검토 표시가 있는지 확인한다.
- 저장 산출물의 주문번호·연락처·주소·결제정보 노출을 확인한다. VOC 통계와 리뷰 수는 제공된 원자료에서 다시 센다.
- FAQ의 정책 설명을 실제 셀러 정책 문서와 대조한다. 정책 문서가 없으면 정확성을 PASS로 판정하지 않는다.

보고서는 `판정(PASS/FAIL/미확인)`, `확인 자료`, `판정·수치별 근거`, `심각도·위치·근거가 있는 발견`, `미검증 항목`으로 작성한다. 핵심 근거가 없으면 그 범위를 PASS로 판정하지 않는다. 독립된 검수자를 실행하지 않았다면 독립 감사라고 부르지 않는다.

## GIL 연결 (v2.5.0)

- **검수 대상 산출물**: `gil:draft-response` · `gil:ticket-triage` · `gil:escalation-manager` · `gil:kb-article`
- **◆최종본 게이트**: 에이전트 `gil:support-ticket-triage-batch`가 ◆최종본을 마감하기 전에 이 검수를 1회 실행한다. ⚡초안·◐작업본에는 자동으로 붙이지 않는다(common-rules §1 등급제).
- **판정 규칙**: 같은 세션에서 산출물을 만든 주체의 자기 검수는 `자체 검수`로 표기하고 독립 감사라고 부르지 않는다. 확인 불가 항목은 `미확인`으로 분리해 PASS에 섞지 않는다.
- **보고서 한국어 품질**: 검수 보고서 자체가 ◆최종본으로 외부 전달되면 `gil:ai-slop-reviewer` → `gil:humanize-korean` 체인을 적용한다.
