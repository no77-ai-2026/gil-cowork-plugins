# 게시 게이트 (Publication Gate)

검수 레코드에 명시된 정확한 후보에 대해 이 게이트를 적용합니다. 목적은 미해결 마케팅 제작 위험을 드러내고, 범위가 한정된 결정을 이름이 명시된 사람 담당자에게 넘기는 것입니다. 법률 자문·법적 승인·규제 인증·플랫폼 승인·게시 허가가 아닙니다.

## 1. 검수 경계 확정

요건을 해석하기 전에 실제 시장·배포 맥락을 기록합니다.

- 국가, 주·도, 지역, 언어, 통화, 게시 예정일
- 유료 광고, 오가닉 게시물, 마켓플레이스 리스팅, 상세페이지, 웹사이트, 앱스토어, 이메일, SMS, 메신저, 크리에이터 계정, 인쇄, 옥외, 방송, 매장 내, 기타 지면
- 대상, 연령 경계, 타게팅·제외 로직, 민감·규제 맥락 여부
- 오퍼 유형, 판매자·제공자, 거래 경로, 랜딩, 책임 사업 담당자
- 정확한 카피·자산·크롭·레이아웃·자막·썸네일·최종 렌더·오퍼·랜딩 버전 식별자

관할·채널·언어·오퍼·렌더가 실질적으로 다르면 각각 따로 검수합니다. 브랜드 차원의 일반 승인이 채널 변형을 자동으로 덮지 않습니다.

## 2. 검수 시점의 공식 출처 기록

기억이 아니라 검수를 수행하는 시점에 현재 1차 출처를 조회합니다.

해당하는 경우 다음을 사용합니다.

- 공식 법령·규정·규제기관 지침·공공기관 고시·공인 등록부
- 실제 플랫폼의 공식 광고·커머스·메시지·크리에이터·접근성·기술 정책
- 현재 1차 제품·서비스 기록, 승인된 증거, 가격·재고 시스템, 계약, 릴리스, 라이선스, 브랜드 정책
- 활성 산업 스킬이 지정한 현재 도메인 권위 출처

의존한 출처마다 제목, 발행처, 직접 URL 또는 내부 기록 ID, 발행·갱신일, 시행일, 조회 일시, 만료·재확인 트리거, 관할, 채널, 관련 요건, 검수 레인을 기록합니다. 발행일·시행일이 표시돼 있지 않으면 `unknown`으로 적고 절대 만들어 넣지 않습니다. 게시 예정일에 시행될 미래 규칙이 있는지 확인합니다. 규칙이 접근 불가·모순·구식·만료·검수자 전문 밖이면 격차를 기록하고 후보를 `draft-only` 또는 `blocked`로 유지합니다.

블로그·검색 스니펫·AI 요약·저장된 기억·경쟁사 행동은 권위 출처를 찾는 데 도움이 될 뿐, 공식 출처를 대체하지 않습니다. 필요한 만큼만 인용하고 출처의 범위·예외·시행일·정의를 보존합니다.

### official_sources[] 스키마

```yaml
official_sources:
  - title: ""
    publisher: ""
    url: ""
    published_or_updated: "unknown | date"
    effective_date: "unknown | date"
    accessed_at: ""
    expires_or_recheck: "before publication | date | trigger"
    applies_to: ""
    review_lane: "A | B | C | D | E"
```

**`unknown` 규칙**: 출처 페이지에 날짜가 없으면 `unknown`. 추정·유사 문서 날짜·조회일로 대체하지 않는다. `unknown`이 남은 출처는 담당자 인계 패킷의 "미해결 판단 사항"에 올린다.

## 3. 레인 A — 주장과 증거 (claims_and_evidence)

단어·이미지·시연·자막·캡션·보이스오버·후기·비교·차트·UI 상태·비포애프터·생략을 포함해 명시적·합리적 암시 주장을 모두 검토합니다.

주장마다 기록합니다.

- 정확한 주장 문구 또는 시각적 암시와 위치
- 증거 소유자, 증거 산출물, 날짜, 방법, 모집단·표본, 조건, 한계, 시장, 만료·재확인일
- 증거가 정확한 강도·범위·기간·비교·전형성·대상 해석을 뒷받침하는지
- 필요한 한정·고지와 그것이 최종 렌더에서 명확하고 인접하게 남는지
- 잔여 위험을 수용해야 하는 이름이 명시된 주제 담당자

외관·스톡 영상·생성 이미지·단일 후기·약한 연구에서 나온 추론을 검증된 제품·결과 사실로 승격하지 않습니다. 증거가 없거나 불일치하면 초안에서는 주장을 제거·축소하고, 근거 없는 버전의 게시는 막습니다.

한국 문구 적법성(표시광고법·식약처·전상법)은 `gil-commerce:commerce-ad-claim-compliance-kr` 결과를 이 레인의 입력으로 흡수합니다.

반환: `{findings[], missing[], required_actions[]}`

## 4. 레인 B — 오퍼와 거래 (offer_and_transaction)

광고·최종 렌더를 실제 거래 경로와 대조합니다.

- 판매자·제공자 신원, 제품·서비스 신원, 자격, 지역, 재고·가용성, 시점, 수량, 실질적 제외 사항
- 가격, 통화, 필수 수수료, 세금 처리, 구독·갱신, 할부, 할인 기준, 쿠폰 조건, 배송, 반품, 취소, 환불, 보증, 마감
- CTA, 랜딩, 결제·예약 상태, 폼 필드, 데이터 수집, 확인, 클릭 후 연속성
- 희소성·긴급성·절약·무료·보증·체험·순위·가용성·총액 진술과 현재 1차 기록의 대조

정확한 크리에이티브도 낡은 랜딩이나 불일치 결제를 통과시키지 못합니다. 거래 사실이 빠지면 `draft-only`, 기만적 가격·가짜 희소성·재고 없음·실질적으로 불일치한 랜딩은 교정 전까지 `blocked`일 수 있습니다.

반환: `{findings[], missing[], required_actions[]}`

## 5. 레인 C — 아웃바운드 메시지 (outbound_messaging)

이메일·SMS·메신저·푸시·DM·리드 아웃리치·리마케팅 등 수신자 지정 커뮤니케이션에 적용합니다. 실제 관할·서비스 기준으로 확인합니다.

- 적법·플랫폼 허용 수신 근거, 명단 출처, 대상 억제, 연령 규칙, 민감 정보 제한
- 발신자 신원, 제목·미리보기 정확성, 광고 표시, 연락처, 빈도, 시점, 야간 제한, 필수 기록
- 동의·철회 상태, 작동하는 수신거부 경로, 억제 동작, 회신 처리, 거래성 vs 광고성 분류
- 개인화 입력, 자동 결정·AI 고지, 링크 목적지, 추적, 개인정보 고지, 데이터 최소화

검수 과정에서 테스트 메시지나 실제 메시지를 보내지 않습니다. 수신 근거·동의·발신자 신원·필수 고지·수신거부 동작이 미지이면 `draft-only`로 두고 발송을 막습니다.

한국 정통망법 판정은 `gil-commerce:commerce-marketing-compliance-kr` 결과를 이 레인의 입력으로 흡수합니다.

반환: `{findings[], missing[], required_actions[]}`

## 6. 레인 D — 보증·크리에이터·권리 (endorsement_creator_and_rights)

보증의 진실성과 모든 요소의 사용 권리를 함께 검토합니다.

- 경제적 이해관계, 대가, 증정, 제휴, 고용, 협찬, 대행, 브랜드 통제 고지
- 보증인 신원, 실제 경험, 승인 문구, 전형성, 주장 근거, 편집 무결성, 합성·배우 여부, 재사용 범위
- 크리에이터·출연자·모델·참석자·환자·학생·직원·아동·자산·장소·예술품·음악·음성·상표·로고·아카이브·스톡·생성 미디어 권리
- 동의·릴리스의 목적, 채널, 지역, 기간, 편집권, 유료 증폭, 화이트리스팅, 독점, 철회·삭제 절차, 크레딧 요건
- 프라이버시, 기밀, 문화적 권위, 공동체 이익, 신성·민감·의료·금융·고용·미성년 관련 제한

고지는 거짓 주장이나 빠진 권리를 치유하지 않습니다. 불명확한 소유권, 만료된 범위, 미고지 이해관계, 조작된 경험, 무단 식별 가능 인물·보호 저작물은 해당 버전의 게시를 막습니다.

반환: `{findings[], missing[], required_actions[]}`

## 7. 레인 E — 도메인·플랫폼·최종 렌더 (domain_platform_and_final_render)

### 도메인과 플랫폼

- 활성 `industry_direction`의 `claim_ledger`, `required_disclosures`, `prohibited_or_high_risk`, `human_review_gate` 통제를 적용한다.
- 정확한 채널·지면·대상·포맷·랜딩·게시일마다 현재 공식 규칙·기술 사양을 확인한다.
- 플랫폼·지면·스토어프런트·아웃바운드 채널·업로드·예약·라이브 운영이 지정된 경우 `gil-creative:meta-ads-manager/references/platform-publication-adapter.md`의 공유 어댑터를 완성한다. 어댑터의 현재 출처·변경 통제는 이 레인의 필수 입력이며 다른 제작 스킬이 생략할 수 없다.
- 도메인별 한정·경고·접근성·전문가 검토·안전·타게팅·가격·기록 보존·금지 콘텐츠 게이트를 확인한다.
- 출처나 규칙이 충돌하면 두 해석을 모두 보존하고 범위·날짜를 밝힌 뒤, 쉬운 쪽을 조용히 고르지 말고 담당자에게 에스컬레이션한다.

### 최종 렌더

스크립트·레이아웃 파일·프롬프트만이 아니라 실제 내보낸 자산을 검사합니다.

- 승인된 카피·숫자·제품/서비스 신원·라벨·로고·오퍼 조건·CTA·캡션·자막·대체텍스트·크레딧이 모두 정확한가
- 고지·한정이 읽히고, 필요 시 들리고, 충분히 지속되고, 주장에 인접하며, 크롭·폴드·잘림·인터페이스 크롬·세이프 에어리어·모션·대비·압축에 가려지지 않는가
- 크롭·레이아웃·합성·리터칭·생성 콘텐츠·재생 속도·순서·썸네일·사운드가 새로운 오해를 만들지 않는가
- 랜딩·제품 상태·가격·가용성·언어·비율·길이·파일 포맷·접근성 처리·플랫폼 미리보기가 검수한 지면과 일치하는가
- 임시 텍스트·플레이스홀더·숨은 레이어·불안전 지시·개인정보·메타데이터 유출·미허가 요소·의도치 않은 변형이 남아 있지 않은가

안정적인 최종 렌더 식별자를 확보합니다. 검수한 내보내기를 정확히 식별할 수 없으면 `draft-only`를 넘어갈 수 없습니다.

반환: `{findings[], missing[], required_actions[]}`

## 8. 상태 계산

최상위 상태는 다음 네 가지만 사용합니다.

| 상태 | 의미 | 게시 결과 |
|---|---|---|
| `blocked` | 금지·불안전·기만·무단·실질적 근거 부족 요소가 남아 있음 | 게시 불가. 요소를 교정하거나 에스컬레이션 |
| `draft-only` | 초안 작업은 가능하나 사실·증거·출처·권리·고지·버전 ID·검수자 정보가 불완전 | 게시·발송 불가 |
| `ready-for-named-human-review` | 고정 버전에 대해 5레인·공식 출처 점검 완료, 결정 대기 중인 담당자 지정됨 | 담당자가 결정을 기록할 때까지 게시 불가 |
| `reviewed-by-named-owner` | 담당자가 정확한 고정 버전에 대해 범위 한정 결정을 기록함 | 기록된 결정과 조직 릴리스 절차를 따름. 법적 승인 아님 |

**레인 결과를 평균 내지 않습니다.** 하나의 material blocker가 자산을 지배합니다. 배치는 독립 자산을 별도 레코드로 나누거나 가장 낮은 미해결 상태를 씁니다. Claude는 어떤 경우에도 `reviewed-by-named-owner`를 스스로 기록하지 않습니다.

## 9. 버전 무효화와 재검수

검수 범위에는 카피·오퍼·랜딩·각 자산 변형·각 최종 렌더의 불변 또는 안정 ID가 포함돼야 합니다. 옛 검수는 감사 기록으로 보존합니다.

### 무효화 트리거 목록

다음 중 하나라도 바뀌면 검수를 무효화합니다.

- 헤드라인, 본문, 자막 텍스트, 캡션, 번역, 보이스오버, 자막, CTA, 가격, 오퍼, 한정, 고지, 크레딧, 법적 문구
- 크롭, 레이아웃, 비율, 텍스트 크기·위치, 순서, 길이, 썸네일, 합성, 리터칭, 오디오 믹스, 내보낸 파일
- 대상, 타게팅, 관할, 채널, 지면, 랜딩, 판매자, 가용성, 게시 시점, 의존한 공식 정책
- 증거, 권리, 동의, 계약, 라이선스, 담당자, 실질적 산업 지침 통제
- 파일이 그대로여도: `recheck_by` 경과, 증거·권리 기록 만료, 출처 만료·대체, 게시일 이전 시행되는 규칙

바뀐 파생본은 `draft-only` 이하에서 시작합니다. 영향 레인과 최종 렌더 점검을 다시 돌리고, 새 식별자·출처를 기록한 뒤, 담당자에게서 새 결정을 받습니다. 옛 검수를 새 버전을 덮는 것으로 다시 라벨링하지 않습니다.

## 10. 설치된 전문 스킬 위임 (선택)

사용자가 요청했거나 미해결 전문 질문이 있고, 해당 스킬이 실제로 설치·호출 가능할 때만 범위가 한정된 질문을 넘깁니다.

| 질문 | 위임 대상 | 소비 레인 |
|---|---|---|
| 한국 광고 주장·증거·오퍼·표시 | `gil-commerce:commerce-ad-claim-compliance-kr` | A |
| 한국 아웃바운드 메시지 분류·동의·발신자·수신거부·발송 규칙 | `gil-commerce:commerce-marketing-compliance-kr` | C |
| 크리에이터 협업·이해관계·계약·산출물·고지 | `gil-commerce:commerce-influencer-collab` | D |
| 관할별 1차 법령·공식 지침 조사 | `gil:law-research`, `gil:legal-risk` (해당 번들 설치 시) | 관련 레인 |
| 식품·화장품·건강기능식품·의약품·성분·식약처 안전 | `gil:mfds-safety` (해당 번들 설치 시) | 도메인 패킷 + A/E |

반환 결과는 `specialist_handoffs[]` 레코드로 흡수하고 범위·날짜를 보존한 뒤, 최종 검수를 정확한 카피·자산 버전에 독립적으로 결속합니다. 미설치면 그렇다고 말하고, 빠진 전문·출처 검토 때문에 게시를 보류하는 검수 기록으로 계속 진행합니다. 전문 스킬 결과는 현재 공식 출처 검증이나 사람 검토를 대체하지 않습니다.

## 11. 검토자 인계 패킷

담당자에게 압축된 결정 패킷을 전달합니다.

1. 정확한 검수 범위와 버전 식별자
2. 제안 상태와 모든 게시 blocker
3. 레인별 발견 사항과 구체적 수정안
4. 발행처·제목·URL·날짜·범위·충돌을 포함한 공식 출처
5. 미해결 판단 사항과 사업 영향
6. 결정 선택지 `approved-within-scope`, `changes-required`, `rejected`
7. 무효화 조건과 재확인일

### named_review_owner.decision

```yaml
named_review_owner:
  name: ""
  role: ""
  authority_scope: ""
  decision: "pending | approved-within-scope | changes-required | rejected"
  decided_at: ""
```

담당자가 실제로 결정한 것을 기록합니다. **침묵·"괜찮아 보임"·이전 캠페인 승인·도구 결과는 정확한 현재 버전에 대한 담당자 검토가 아닙니다.** `release_note`는 고정 문구 "사람 검토 기록이며 법적 승인·게시 권한이 아님"을 유지합니다.
