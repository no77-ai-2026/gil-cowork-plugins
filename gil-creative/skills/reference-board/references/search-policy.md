# 레퍼런스 검색 정책 (search-policy)

레인 공통 규칙입니다. 레인별 출처 allowlist는 [lanes.md](lanes.md), Pinterest 표시 경로는 [reference-preview-contract.md](reference-preview-contract.md)를 참조합니다.

## 핵심 규칙

- 검색어는 "무엇을 찍는가(주제)"를 식별하고, "어떻게 찍는가(스타일)"를 담지 않습니다.
- `target_count`는 사용자의 양의 정수 지정값, 없으면 `6`. 최종 보드는 정확히 `target_count`장의 서로 다른 이미지를 현재 대화 안에 직접 보여야 합니다. 링크 보드·HTML 파일·컨택트시트·별도 아티팩트는 인라인 보드가 아닙니다.
- 한 보드는 한 레인. 레인 allowlist 밖의 도메인은 검색·열기·클릭·가져오기·미리보기·보관·노출 어느 것도 하지 않습니다.

## 검색어 깊이(업종 taxonomy)

`gil-creative:industry-overlay/references/industry-taxonomy.json`(설치 시)을 읽고 taxonomy를 최대 2단계만 씁니다. 검색 계획은 L1 광의 카테고리 1개 + 직접 L2 하위 유형 0~1개입니다.

1. 요청을 하나의 도메인·하나의 가지로 분류한다
2. 그 가지의 정확한 `l1` 검색어를 먼저 실행한다
3. 주제와 직접 일치하는 `l2Examples` 값을 최대 1개 실행한다
4. 목록에 없는 주제는 그 주제 하나만 가지의 `medium`으로 정규화한다. 수식어나 복합 개념이 더 필요하면 L1에서 멈춘다
5. L1·L2·창작 속성을 이어 붙인 롱테일 검색어를 만들지 않는다

L2는 L1의 직접 자식이지 "L1 + 수식어 나열"이 아닙니다. 업종 방향 패킷은 가지와 직접 하위 유형을 고를 수 있지만, 시각 속성은 발견 뒤 순위 기준으로만 남습니다.

| 입력 | 광의(L1) | 직접 하위(L2) |
|---|---|---|
| 화장품 세럼 | Cosmetic Photography | Serum Photography |
| 블러셔 | Cosmetic Photography | Blush Photography |
| 립스틱 | Cosmetic Photography | Lipstick Photography |
| 핫도그 | Food Photography | Hotdog Photography |
| 버거 | Food Photography | Burger Photography |
| 커피 음료 | Beverage Photography | Coffee Photography |
| 헤드폰 | Product Photography | Headphone Photography |
| 핸드백 | Fashion Accessories Photography | Handbag Photography |
| 법무법인 | Professional Services Branding | Law Firm Branding |
| 호텔 | Hospitality Photography | Hotel Photography |
| 인테리어 | Architecture Photography | Interior Photography |
| 전기차 | Automotive Photography | Electric Vehicle Photography |

taxonomy 파일이 없으면 위 표를 기준으로 같은 형태(`<주제> Photography` / `<주제> Branding`)로 정규화하되 여전히 2단계를 넘지 않습니다.

## 금지 수식어

검색어에 다음을 추가하지 않습니다.

- 색·팔레트·배경·소품·계절·환경
- 조명·그림자·카메라·렌즈·앵글·조리개
- 분위기·미학 형용사
- 비율·플랫폼명·포스터·배너·레이아웃 단어
- premium·luxury·cinematic·creative 등 품질어
- award·winner·best·trendy 등 평가어
- 브랜드명·캠페인명·사진가·에이전시·슬로건·카피
- 트렌드 이름·연도·팔레트명·무드·스타일 단어

제공자·도메인 범위는 라우팅 메타데이터이지 의미 검색어의 일부가 아닙니다.

## 발견 호출 상한과 자동 복구

- 레인당 발견 호출 최대 6회(페이지네이션·동의어 포함).
- 연속 2회 새 후보가 없으면 중단. 목표 표시 수 도달, 접근·속도 제한·전송 차단 관찰 시에도 중단.
- 같은 L1/직접 L2 범위 안의 철자·단복수·동의어·페이지네이션·같은 제공자의 다른 검색 표면·미사용 후보 교체는 자동. 사용자에게 "추가 검색 허용"을 묻지 않습니다.
- L3나 창작 수식어를 더한 좁은 검색어로 재시도하지 않습니다. L2가 불확실하면 L1에 머뭅니다.
- 미리보기(표시) 시도는 목표 수의 3배까지. 실패한 후보를 맹목적으로 재시도하지 않습니다.
- 인증·표시 실패는 의미 검색을 더 한다고 해결되지 않습니다.

## 수집

- `target_count` + 합리적 교체분을 덮을 만큼 후보를 모읍니다(도구의 호출당 결과 한도 안에서, Pinterest 검색은 호출당 8건 상한).
- 보존 필드: 레인·미리보기 URL·출처 페이지 URL·제목·작가/보드/광고주(보이는 경우)·출처 도메인·크기(알 때)·검색어. 아웃바운드 목적지 필드는 폐기.
- 중복 병합: 정규 ID/URL, 크기 세그먼트·쿼리를 제거한 미리보기 자산 경로, 지각적 근사 중복, 한 이미지의 다른 크롭, 아카이브 간 같은 캠페인.
- 거부: 콜라주·스크린샷·심한 압축·주제 위 워터마크·텍스트 지배 이미지·접근 불가 미리보기·출처 페이지 없음·고아 항목·로그인 게이트·스크랩 미러·이미지-페이지 짝 불확실·한 촬영의 중복 크롭·영상 전용 항목(스틸 없음).
- 대화 표면이 직접 렌더할 수 있는 미리보기를 요구합니다.
- 접근 통제 우회·스크래핑·대량 다운로드 금지.

## 채점(0~100)

| 기준 | 가중치 | 질문 |
|---|---:|---|
| 주제 호환성 | 25 | 이 비주얼 체계가 원본 주제를 담을 수 있는가 |
| 전이 가능한 구도 | 20 | 프레이밍·스케일·여백을 다시 적용할 만큼 명확한가 |
| 조명 가독성 | 20 | 방향·광원 크기·대비·그림자를 추론할 수 있는가 |
| 재질·음식 호환성 | 15 | 처리 방식이 원본 표면·질감을 지지하는가 |
| 제작 실현성 | 10 | 주제를 숨기거나 재설계하지 않고 장면을 만들 수 있는가 |
| 오염 위험 | 10 | 타사 로고·패키지·카피·인물·레시피 특징을 배제하기 쉬운가 |

## 다양성과 출처 분산

3장 이상이면 다음 6축 중 최소 3축이 다른 세트를 만듭니다. 1~2장이면 다양성을 지어내지 않고 의미 있는 차이만 극대화합니다.

1. 중앙 vs 비대칭 구도
2. 하이키 vs 로우키 조명
3. 딱딱한 vs 부드러운 그림자
4. 평면 vs 입체 세트
5. 미니멀 vs 소품 지원 장면
6. 정면 vs 하이앵글 vs 탑뷰

정확히 `target_count`장을 고르고, 한 작가·한 촬영이 지배하지 않게 합니다. 자동 복구 뒤에도 부족하면 통과한 부분집합을 보여주고 미완성으로 표시한 뒤 요청/표시/부족 수를 밝힙니다. 다른 레인으로 교차 보충하거나, 실패 후보를 재활용하거나, 기준을 낮추지 않습니다.

## 인라인 표시 의무

- 모든 최종 후보를 응답 안에 실제 이미지로 렌더합니다. 사용자가 다른 페이지를 열지 않고 후보 전체를 비교할 수 있어야 합니다.
- 전송 우선순위: `mcp-image-content` > `native-image-content` > `image-attachment` > `verified-inline-embed`.
- `display_confirmed`는 실제 이미지 콘텐츠가 현재 대화에 나타난 뒤에만 `true`. 한 후보라도 표시되지 않으면 보드는 미완성입니다.
- 호스트에 이미지 콘텐츠·첨부 경로가 전혀 없으면 한 번만 한계를 밝히고 출처 링크·HTML 보드를 선택적 폴백으로 제안합니다. 그 폴백을 인라인 보드라고 부르거나, 이미지가 보인 것처럼 선택 체크포인트를 진행하지 않습니다.

## 권리와 출처

- 모든 레퍼런스는 방향 참고 전용(`rights_status: "direction-only"`). 상업적 재사용 라이선스를 추론하지 않습니다.
- 출처 페이지(Pin·작품·케이스·갤러리 항목)를 유일한 링크로 유지하고, 아웃바운드 목적지를 열거나 보관하거나 노출하지 않습니다.
- 픽셀 직접 재사용 요청은 멈추고 권리를 별도로 확인합니다.
